## 1. เป้าหมายและเกณฑ์ผ่าน (Definition of Done)

ตรวจฝา/ขอบฝากระป๋องที่**เคลื่อนที่ผ่านจุดตรวจ 7-12 ใบ/วินาที** ให้ได้:

- ภาพนิ่งคม (ไม่มี motion blur ที่มองเห็น) 1 ภาพต่อกระป๋อง 1 ใบ ทุกใบ
- ตัดสิน NG/OK ทันภายในงบเวลา (ดูตาราง §3)
- **Escape (NG หลุดเป็น OK) ≤ 1% และ False alarm (OK โดนทักเป็น NG) ≤ 2%**
  บนชุดทดสอบ blind ≥ 200 ใบ ที่ความเร็วเป้าหมาย
- ผลขึ้นจอ + ลง DB (ใช้ Dashboard/DB เดิมของระบบ) — ยังไม่ต้องดีดของออก

## 4. สถาปัตยกรรม (แบบเดียวกับระบบพาณิชย์ — triggered ไม่ใช่ free-running)

```
Photo-eye (24V) ──► trigger input ของกล้อง (hardware, µs-precision; PC ไม่เกี่ยวจังหวะถ่าย)
                        │  (ตั้ง trigger delay ในกล้องให้ฝาอยู่กลางเฟรม)
                        ▼
        กล้อง global shutter + exposure ~150-200µs + ไฟ LED แรงสูง
                        │  GigE → PC
                        ▼
        [ซอฟต์แวร์ใหม่: triggered mode]  ROI crop → infer imgsz 480 → verdict
                        │
                        ▼
        จอ monitor + DB log (ของเดิม)          ← เฟสนี้จบแค่นี้ (ไม่มี reject)
```

เหตุที่ต้อง triggered (บทเรียนที่สรุปแล้วใน session ก.ค. 2026):
- ที่ 7.5+ ใบ/วิ ช่องว่างระหว่างใบสั้นกว่าคาบเฟรม → ตรรกะนับแบบ "เฟรมว่าง" (ของ live mode ปัจจุบัน) พังสนิท
- free-running ต้องการ 75-150fps + ภาพยังเบลอ → ตัน; triggered ใช้ 1 เฟรมคุณภาพสูงสุด/ใบ ภาระเครื่องลด ~10 เท่า
- เฟรมเรตกล้องแทบไม่สำคัญ (≥12fps พอ) — สเปกที่ชี้ขาดคือ **global shutter + exposure ต่ำ + trigger input**

## 6. แสง — ตัวตัดสินความสำเร็จอันดับหนึ่ง (จากระบบจริง + งานวิจัย)

dent บนโลหะสะท้อนแสงเป็น "โจทย์แสง" ก่อนเป็นโจทย์ AI: ผิวปกติสะท้อนแสงทิ้ง ผิวบุบเบี่ยงแสงเข้ากล้อง

- **ฝา (ผิวแบนวงกลม): dark-field / low-angle ring** — ไฟเฉียงต่ำเกือบขนานผิว: ฝาเรียบ = มืด, รอยบุบ/ยับ = สว่างเด่ง. งานวิจัยปี 2025 ยืนยัน grazing-angle คือมุมเดี่ยวที่ดีที่สุดสำหรับ defect เล็กบนโลหะเงา. ระบบพาณิชย์ Filtec ECI (ตรวจได้ถึง 2,400 CPM) ใช้ "dual circular top lighting" หลักการเดียวกัน
- **ขอบฝา (flange, ขอบโค้งยกขึ้น): แสงเฉียงต่ำจากด้านข้าง** — ขอบปกติสะท้อนเป็นวงแหวนสว่างสม่ำเสมอ ขอบบุบทำให้วงแหวนแหว่ง/บิด (มองเห็นง่ายทั้งต่อคนและโมเดล)
- เกณฑ์ตัดสินตอนทดลอง rig: **ถ้าตาเปล่าดูภาพถ่ายแล้ว dent เด่งชัด = ชนะไป 80%** — โมเดลจะเรียนรู้จากภาพแบบนี้ง่ายกว่าภาพแสงห้องมหาศาล (และเปิดทางให้ใช้โมเดลเล็กลง → เร็วขึ้น → รองรับ 12 ใบ/วิ)
- ไฟต้อง**แรงพอให้ exposure ~150-200µs สว่างพอ** — นี่คือเหตุผลที่ไฟเป็นงบก้อนใหญ่อันดับสองรองจากกล้อง (ต่อ strobe/overdrive ผ่านขา output ของกล้องได้ถ้าไฟต่อเนื่องไม่พอ)

## 7. ค่าตั้งกล้องแนะนำ (จุดตั้งต้นตอนประกอบ rig)

| ค่า | ตั้งต้น | เหตุผล |
|---|---|---|
| TriggerMode / TriggerSource | On / Line0 (photo-eye) | 1 trigger = 1 ใบ = 1 verdict |
| Trigger delay | จูนหน้างาน (µs) ให้ฝากลางเฟรม | วาง photo-eye ให้ delay ≈ 0 จะทนความเร็วแกว่งที่สุด |
| Exposure | 150-200 µs (เผื่อ worst-case 12 ใบ/วิ) | blur = v × t ≤ 0.2mm |
| Gain | ต่ำสุดที่ภาพสว่างพอ | gain สูง = noise ซึ่งกลืน dent ตื้น |
| FOV | เส้นผ่านศูนย์กลางฝา × ~1.4 (ฝากิน ~70% ของเฟรม) | พิกเซลบนตัวกระป๋องคือสิ่งที่โมเดลเห็นจริง — อย่าถ่ายกว้างเกิน |
| imgsz | **480** (+ ROI crop จากภาพเต็มเมื่อจำเป็น) | verdict เท่า 1280 เมื่อฝาเต็มเฟรม (ทดลองแล้ว) ที่ความเร็ว 45-78ms; **ห้ามต่ำกว่า 480** (กฎ repo) |
| conf threshold | เริ่มที่ค่า production เดิม แล้วจูนจาก blind test | ห้ามจูนตามความรู้สึก |

## 8. ซอฟต์แวร์ที่จะเขียน (เมื่อได้รับคำสั่ง — โครงร่างไว้ก่อน)

**หลักการ scope เดิมของ repo: opt-in ทั้งหมด, โหมดเดิมไม่กระทบ 100%, ผ่าน verify ก่อนใช้จริง**

1. **`triggered_inspect.py` (สคริปต์/โหมดใหม่ แยกจาก Flask loop):**
   Hikrobot MVS SDK (Python) callback ต่อ trigger → เฟรม → (ROI crop ถ้าตั้ง) →
   `YOLODetector.detect(imgsz=480)` (ใช้ backend OpenVINO iGPU + fallback chain เดิมทั้งชุด) →
   verdict + per-can latency → จอ + DB (log แบบ async queue — อย่า block เส้นทางตรวจ)
2. **โหมดเก็บ dataset:** ปุ่ม/flag ให้บันทึกภาพ triggered ทุกใบลงโฟลเดอร์ (ไว้เทรน/verify)
3. **เครื่องมือวัด:** สรุป ms/ใบ (p50/p95/max), นับใบที่พลาด trigger, ใบที่ infer ไม่ทันงบ
4. ถ้า 12 ใบ/วิ แล้ว 45-78ms ไม่พอจริง: ลำดับแก้ = (ก) เทรน detection/รุ่น s บนภาพแสงใหม่ (โจทย์ง่ายขึ้นมาก ดู §6) (ข) dGPU + TensorRT (YOLOv8n ~8-10ms บน RTX 4060; seg ~2.7ms บน RTX 5070Ti — ตัวเลข benchmark สาธารณะ)

## 9. Dataset + โมเดล (ความเสี่ยง #1 ฝั่ง AI = domain shift)

- `bestX.pt` เทรนจากภาพ webcam + แสงห้อง — **ห้าม assume ว่าใช้ได้กับกล้อง/ไฟใหม่** (บทเรียนเดียวกับ OpenVINO: ห้ามเชื่อจนกว่า verify)
- ขั้นตอน: เก็บภาพจาก rig จริง 300-500 ใบ (ปน dent ฝา/ขอบหลายระดับ + ใบดี) → รัน bestX เดิมดู baseline → เทรนใหม่/fine-tune → **verify ด้วย harness มาตรฐานของ repo** → blind test ตามเกณฑ์ §1
- เคสทดสอบที่ต้องมี: **ใบที่มี dent เดี่ยวจางๆ** (ตัววัด escape จริง — ใบ dent เยอะ verdict รอดแม้บางจุดหลุด) และใบดีล้วน (วัด false alarm)
