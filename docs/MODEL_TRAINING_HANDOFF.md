## §2 · ชื่อคลาสคือ "สัญญากับโค้ด" ไม่ใช่แค่ป้ายกำกับ

ในระบบมีบรรทัดนี้อยู่จริง (`app.py`):

```python
_NON_DEFECT_CLASSES = {"good", "can"}
```

**อะไรก็ตามที่ไม่ใช่สองคำนี้ = ถูกนับเป็นของเสีย + บันทึกลงฐานข้อมูล SQL Server ทันที**

และบรรทัดนี้ (`yolo_detector.py`) เป็นตัวตัดสิน NG/OK:

```python
if any(d["class_name"] == "dent"):  return "ng"   # มีรอยบุบ = เสีย
if any(d["class_name"] == "can"):   return "ok"   # เจอกระป๋อง ไม่มีรอย = ดี
```

### ตัวอย่างที่ผิด (เจอบ่อย)

| ชื่อที่ตั้ง | ผลที่เกิด |
|---|---|
| `Can` (C ใหญ่) | กระป๋องทุกใบถูกนับเป็นของเสีย |
| `dented` (มี ed) | **badge NG ไม่ขึ้นเลย** ระบบคิดว่าไม่มีของเสีย |
| `dent ` (เว้นวรรคท้าย) | เหมือนข้างบน |
| เพิ่ม `scratch` เป็นคลาสที่ 3 | ถูกนับเป็นของเสียโดยที่ระบบไม่รู้ว่ามันคืออะไร |

> ⚠️ ใน `data.yaml` ที่ส่งกลับมา **ต้องมีแค่**
> ```yaml
> names:
>   0: can
>   1: dent
> ```

## §3 · กติกาการ Label (สำคัญที่สุด — สำคัญกว่าฝีมือเทรน)

### กฎข้อ 1 — ทุกใบต้องมี `can` เสมอ รวมถึงใบที่บุบ

```
❌ ผิด:  ใบบุบ → ลากแค่ dent
✅ ถูก:  ใบบุบ → ลาก can ครอบทั้งใบ + dent ทับบนรอย
```

**เหตุผลจากโค้ดจริง** — ฟีเจอร์ "ภาพแช่" ใช้กล่อง `can` ตัดสินว่ากระป๋องอยู่ในเฟรมครบใบไหม:

```python
body = [d for d in detections if d["class_name"] in _NON_DEFECT_CLASSES]
if not body:
    return False          # ไม่มีกล่อง can = ตัดสินไม่ได้ = ฟีเจอร์ตายเงียบ
```

ไม่ต้องกังวลว่าจอจะรก — ตอนแสดงผลระบบซ่อนกล่อง `can` ให้เองเมื่อพบ `dent`

### กฎข้อ 2 — `dent` ล้อมเฉพาะรอยบุบ ไม่ใช่ทั้งใบ

- 1 ใบมี 2 รอยที่แยกกันชัด → ลาก 2 อัน
- 2 รอยติดกันจนแยกไม่ออก → ลากรวมเป็น 1 อัน
- ขอบ polygon ต้องแนบรอยจริง **ห้ามกินเงาข้างเคียง** (สอนโมเดลว่า "เงา = รอยบุบ")

### กฎข้อ 3 — ต้องมี "ใบดี" ในชุดข้อมูลด้วย

ใบดี = ลาก `can` อย่างเดียว ไม่มี `dent`
**นี่ไม่ใช่ภาพเสียเวลา** แต่คือภาพที่สอนโมเดลว่าอะไร *ไม่ใช่* รอยบุบ

### กฎข้อ 4 — 🔴 นับเป็น `dent` เมื่อไหร่ (ต้องยึดเหมือนกันทั้งชุด)

```
✅ นับเป็น dent:
   - เห็นเงาขอบของรอยยุบชัดเจน (ผิวโลหะยุบลงไปจริง)

❌ ไม่นับ (ปล่อยเป็นใบดี — เก็บไว้เป็นตัวอย่าง "ดูเหมือนเสียแต่ดี"):
   - รอยขีดข่วนที่ผิวไม่ยุบ
   - แสงสะท้อน / เงา
   - คราบสกปรก / เศษผง / หยดน้ำ
   - รอยพิมพ์ฉลากหรือรหัสวันที่ไม่ตรง

🤔 ไม่แน่ใจ → ทิ้งภาพนั้นไปเลย ห้ามเดา
```

> **หลักการของโปรเจกต์นี้: "ผลที่ผิดแบบมั่นใจ แย่กว่าไม่แสดงผล"**
> ภาพที่ลังเลแล้วเดา แย่กว่าไม่มีภาพนั้น เพราะสอนโมเดลผิดโดยตรง

### กฎข้อ 5 — ห้ามใช้ AI auto-label กับ `dent`

- `can` → ใช้ SAM/Smart Polygon ช่วยได้ **แต่ต้องตรวจทุกภาพ**
- `dent` → **ลากด้วยมือเท่านั้น** AI ไม่รู้จักคำว่า "รอยบุบ" มันจะไปล้อมห่วงดึง/ตัวอักษร/ขอบฝา แล้วแปะป้าย `dent` ให้

## §4 · ข้อกำหนดของชุดข้อมูล

### จำนวนขั้นต่ำ

| ระดับ | จำนวนภาพ (หลังกรองภาพซ้ำแล้ว) | ใช้ทำอะไรได้ |
|---|---|---|
| < 50 | ❌ | **เทรนไม่ได้** — ใช้เป็นตัวอย่างสอนกติกาเท่านั้น |
| 100-150 | ⚠️ | พิสูจน์ concept ได้ ยังไม่พอใช้งานจริง |
| **300-500** | ✅ | **เป้าหมายของงานนี้** |

### ความหลากหลาย (สำคัญกว่าจำนวน)

| ต้องหลากหลาย | เกณฑ์ |
|---|---|
| **กระป๋องคนละใบ** | ≥ 30 ใบ — ไม่ใช่ใบเดิมถ่ายซ้ำหลายรูป |
| **การหมุน** | หมุนกระป๋องก่อนถ่ายทุกครั้ง (ห่วงดึงชี้คนละทิศ) |
| **แสง** | อย่างน้อย 3 สภาพแสงต่างกัน |
| **ระดับความบุบ** | ตื้น / ลึก / เล็ก / ใหญ่ / ใบดีสนิท |
| **ตำแหน่งในเฟรม** | กลาง / ริม / เอียง — ไม่ใช่กลางเฟรมทุกใบ |

> **สูตรที่ใช้ได้จริง:** 1 ใบ ถ่าย 3-4 รูป (หมุนคนละมุม) × 30 ใบ ≈ 100-120 ภาพ
> ดีกว่า 500 ภาพของกระป๋องใบเดียวมหาศาล

### 🚨 การแบ่ง train / valid / test — ข้อนี้พลาดบ่อยที่สุด

**ห้ามสุ่มแบ่งรายไฟล์ ถ้าภาพมาจากการถ่ายรัวหรือจากวิดีโอ**

เฟรมที่ถ่ายห่างกัน 1-3 วินาที = ภาพเดียวกันในสายตาโมเดล ถ้าสุ่มแบ่งจะเกิด
**data leakage** → mAP ออกมา 0.95+ แบบหลอก แต่ของจริงตรวจไม่เจอ

**กติกา: กระป๋องใบเดียวกัน ต้องอยู่ split เดียวกันเท่านั้น**
สัดส่วน 70 / 20 / 10

## §5 · เกณฑ์ตรวจรับงาน (Acceptance Criteria)

ส่งงานมาแล้วจะถูกตรวจด้วยเกณฑ์เหล่านี้ — **ผ่านทุกข้อจึงรับ**

| # | เกณฑ์ | ค่าที่ต้องได้ | เหตุผล |
|---|---|---|---|
| 1 | **Recall ของคลาส `dent`** บน test set | **≥ 0.95** | งาน QC: *ปล่อยของเสียผ่าน* แพงกว่า *ฟ้องเกิน* มาก |
| 2 | Precision ของคลาส `dent` | ≥ 0.85 | ฟ้องเกินมากไปคนจะเลิกเชื่อระบบ |
| 3 | mAP50 รวม | ≥ 0.80 | ตัวเลขอ้างอิงรวม |
| 4 | ชื่อคลาสใน `.pt` | `can`, `dent` เป๊ะ | §2 |
| 5 | task ใน `.pt` | `segment` | §1 |
| 6 | ทดสอบบนภาพที่ไม่เคยเห็น | ตรวจเจอจริง | ดู §6 |

> ⚠️ **ถ้า val mAP พุ่งเกิน 0.95 ตั้งแต่ epoch แรก ๆ = สงสัย data leakage ทันที**
> ให้กลับไปตรวจการแบ่ง split ตาม §4 อย่าส่งงานมาก่อน

## §6 · คำสั่งเทรนที่แนะนำ

สถานีปลายทางไม่มี GPU (Intel iGPU เท่านั้น) — **ให้เทรนบนเครื่องที่มี NVIDIA GPU
หรือ Google Colab (T4 ฟรี)** เทรนบน CPU จะใช้เวลาหลายวัน

```bash
pip install ultralytics

yolo segment train \
    model=yolov8m-seg.pt \
    data=/path/to/data.yaml \
    epochs=100 \
    imgsz=640 \
    batch=8 \
    patience=25 \
    device=0
```

| พารามิเตอร์ | ทำไมค่านี้ |
|---|---|
| `model=yolov8m-seg.pt` | ขนาดเดียวกับโมเดล production ปัจจุบัน (27M params) เทียบผลกันได้ตรง |
| `imgsz=640` | **ห้ามลด** — รอยบุบเป็นฟีเจอร์เล็ก |
| `batch=8` | พอดี T4 16GB ที่ imgsz 640 · ถ้า OOM ลดเป็น 4 |
| `patience=25` | หยุดเองถ้าไม่ดีขึ้น 25 epoch — กัน overfit |
| `device=0` | บังคับใช้ GPU (ถ้าลืม มันจะเงียบ ๆ ไปรัน CPU) |

### Augmentation ที่ควร / ไม่ควรใช้ (เชิงฟิสิกส์ของงานนี้)

| ✅ ใช้ได้ | ❌ ห้ามใช้ | เหตุผลที่ห้าม |
|---|---|---|
| Brightness ±15% | **Cutout / Random Erasing** | เจาะรูดำบนภาพ = **สร้างรอยบุบปลอม** หรือลบรอยจริงทิ้งแต่ label ยังอยู่ |
| Exposure ±10% | Hue / Saturation แรง | สีกระป๋องคือข้อมูล ไม่ใช่ noise |
| Rotation ±10° | Shear / Crop แรง | ตัดรอยบุบขาดครึ่งแล้ว label เพี้ยน |
| Flip horizontal | | |
| Blur ≤ 1 px | | |
| Noise ≤ 2% | | |

## §9 · ชุดตัวอย่างมาตรฐาน (Gold Set) — ใช้สอนกติกา

### ขั้นที่ 3.6 — ⚠️ แก้ path ใน data.yaml (กับดักคลาสสิก)

`data.yaml` ที่ Roboflow ให้มาใช้ path แบบสัมพัทธ์ ซึ่งมักพังบน Colab
**ต้องรันช่องนี้ทุกครั้ง** ไม่งั้นจะเจอ error `Dataset not found`

```python
import yaml

p = f"{dataset.location}/data.yaml"
with open(p) as f:
    d = yaml.safe_load(f)

d["train"] = f"{dataset.location}/train/images"
d["val"]   = f"{dataset.location}/valid/images"
d["test"]  = f"{dataset.location}/test/images"

with open(p, "w") as f:
    yaml.dump(d, f)

print(d)   # ⬅️ ต้องเห็น names: ['can', 'dent'] ตรงนี้
```

> 🔴 **บรรทัด print คือด่านตรวจสำคัญ** — ถ้า `names` ไม่ใช่ `['can', 'dent']` **หยุดตรงนี้เลย**
> กลับไปแก้ที่ Roboflow → `Classes & Tags` แล้วสร้าง version ใหม่ อย่าเทรนต่อ

### ขั้นที่ 3.7 — เริ่มเทรน

```python
!yolo segment train \

```

**ระหว่างเทรนให้ดู 2 คอลัมน์นี้:**

| คอลัมน์ | หมายถึง | สัญญาณอันตราย |
|---|---|---|
| `box_loss` / `seg_loss` | ค่าความผิดพลาด | ควรลดลงเรื่อย ๆ · ถ้านิ่งไม่ขยับ = ข้อมูลน้อยเกินหรือ label เพี้ยน |
| `mAP50` | ความแม่นรวม | 🚩 **ถ้าพุ่งเกิน 0.95 ตั้งแต่ 10 epoch แรก = สงสัย data leakage ทันที** |

⏱️ **เวลาที่ใช้โดยประมาณบน T4:** 100 ภาพ ≈ 20-30 นาที · 300 ภาพ ≈ 1-1.5 ชั่วโมง

> ⚠️ **อย่าปิดแท็บ Colab ระหว่างเทรน** — ถ้าไม่มีการโต้ตอบนาน ๆ มันจะตัดการเชื่อมต่อและงานหายหมด

## 🧯 ปัญหาที่เจอบ่อยบน Colab

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `Dataset not found` / `train: not found` | path ใน data.yaml ผิด | รันขั้น **3.6** ซ้ำ |
| เทรนช้ามาก ไม่มี GPU | ลืมเลือก T4 | `Runtime → Change runtime type → T4 GPU` แล้ว **รันใหม่ทั้งหมด** |
| `CUDA out of memory` | batch ใหญ่ไป | ลด `batch=8` → `batch=4` |
| session หลุดกลางทาง | ทิ้งไว้นานไม่โต้ตอบ | เปิดแท็บทิ้งไว้ · สำรองลง Drive ทุก 30 นาที |
| `names` ไม่ใช่ `['can','dent']` | คลาสใน Roboflow ไม่สะอาด | 🔴 **หยุด** กลับไปแก้ `Classes & Tags` → สร้าง version ใหม่ |
| mAP สูงผิดปกติตั้งแต่ต้น | data leakage | กลับไปแบ่ง split ตามใบกระป๋อง (§4) |
